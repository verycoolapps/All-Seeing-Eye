# Decision Engine

## Purpose
Structure decision-making for visual judgment tasks — when to choose between options, how to weigh criteria, how to handle ambiguity, and how to communicate recommendations confidently but honestly.

## Core knowledge
- **Decision frameworks:** weighted criteria (assign importance scores), elimination by constraints (remove impossible options first), pairwise comparison (A vs. B), scoring matrix (rate each option on each criterion), satisficing (good enough vs. optimal).
- **Criteria categories:** aesthetic quality, functional fit, technical feasibility, cost/budget, context appropriateness, user preference, brand/style alignment, maintenance/long-term.
- **Decision types:** binary choice (A or B), ranking (order options), generation (create new option), critique (evaluate without choosing), recommendation (suggest improvement).
- **Handling ambiguity:** when criteria conflict (beautiful but impractical), present trade-offs explicitly; when information insufficient, state assumptions; when user preference unknown, ask or infer from context.
- **Confidence calibration:** high confidence = clear winner on most criteria; medium = close call with trade-offs; low = insufficient information or subjective criteria dominate.
- **Communication:** lead with recommendation, then reasoning, then alternatives; use decisive language for clear wins ("Choose A because...") and hedged language for close calls ("A is slightly better for X, but B wins on Y").
- **Ethical considerations:** don't hide trade-offs to push an agenda; don't recommend what benefits you over user; disclose limitations ("based on image alone, can't assess...").
- **Iteration:** decisions can be revisited with new information; state what would change your recommendation.

## Evaluation criteria / rules
- For any choice task: define criteria → weight them → evaluate options → synthesize recommendation → state confidence.
- When criteria conflict: name the conflict explicitly ("Option A is more beautiful but Option B is more practical — the choice depends on whether this is for show or daily use.").
- For ranking tasks: provide clear ordering with brief justification for each position.
- For generation tasks: generate options that span the solution space (safe/conventional, balanced, bold/experimental) unless brief specifies.
- When user asks "which is better?" give a decisive pick + one-sentence reason; offer alternative only if genuinely close.
- State confidence level: "I'm confident because..." or "This is a close call because..."
- Always mention what you can't assess (missing information, subjective criteria, context you don't have).
- For irreversible/high-stakes decisions: recommend consultation with professional (architect, engineer, designer).

## Confidence & limits
- High confidence: clear technical/functional winner, obvious aesthetic violations, measurable criteria dominate.
- Medium: aesthetic vs. functional trade-offs, style preferences, incomplete information.
- Low: subjective criteria dominate, user preference unknown, insufficient context, cultural factors unknown.
- Cannot decide: user personal taste (only infer), business strategy, ethical trade-offs requiring user values, decisions requiring domain expertise you lack.
- Always state: "Based on available information..." and "What would change my recommendation: ..."
